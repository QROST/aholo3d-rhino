# Mesh placement formats

Maintainer: CuriousArc · qrost.

| Format | Current import boundary |
| --- | --- |
| GLB | Static embedded geometry/materials supported by Rhino. Skins, animation and unsupported required glTF extensions fail before document mutation. |
| PLY | Ordinary polygon mesh with complete finite positions and valid face indices; ASCII and either binary byte order. Complete Gaussian fields use the separate GS importer. |
| STL | Original bytes passed to Rhino's native importer and audited as mesh geometry. |
| 3MF | Independent static mesh reader: core triangles/components/build transforms and base RGBA; direct PNG/JPEG texture groups and uniform per-triangle color groups. Self-contained 3DM candidate. |
| Mesh USD/USDA/USDC/USDZ (local or task result) | Strict static triangles/quads, simple planar n-gons and material face subsets, full transforms, split normal/UV seams, supported Preview Surface factors/direct bitmaps; converted into a self-contained 3DM candidate. |
| OBJ / typed OBJ ZIP | Static simple planar polygons, smoothing/authored normals, used MTL PBR preview and PNG/JPEG diffuse maps; explicit entry/units/up-axis choices; shared self-contained 3DM candidate. Native acceptance pending. |
| FBX archives, untyped ZIP, unsupported 3MF extensions | Retained downloads; integrated placement remains pending. |

Native mesh formats use a private suffix-preserving copy and the original SHA-256, headless native import, actual mesh audit/repair, candidate preview and one Block/Undo commit. Original downloads are retained. Repeated acceptance uses the existing import receipt instead of creating another object. There is no artificial vertex/face ceiling. Native parsing and memory use still depend on Rhino and the machine.

## Independent static 3MF reader

Local and task-result `.3mf` placement now uses a managed decoder followed by the shared self-contained 3DM snapshot, candidate, Block and Undo flow. It does not rely on Rhino's 3MF importer. Original bytes and SHA-256 remain intact. Package reads, XML decoding and mesh preparation observe cancellation; final native 3DM import/commit still uses the existing document/settings/intent guards.

The package checker indexes ZIP parts without extraction and uses `System.IO.Packaging` 8.0.1 OPC URI resolution. It checks duplicate/ambiguous names, content types, primary model selection, all relationship parts, missing/external resources and unsupported markup. XML disables DTDs/external resolution. Valid package-absolute and parent-relative references remain supported. Escaped separators/unreserved characters, nested percent escapes, filesystem paths, references above the root and literal/escaped colons are rejected. This is not full ZIP/CRC/XSD or manufacturing conformance. The older public `ThreeMfPreflight.Validate` compatibility entry stays core-only; admitting texture markup there would not establish native decoder support.

The reader follows the [Core 1.2.3 resource and transform rules](https://github.com/3MFConsortium/spec_core/blob/1.2.3/3MF%20Core%20Specification.md) and a bounded [Materials 1.2.1 subset](https://github.com/3MFConsortium/spec_materials/blob/1.2.1/3MF%20Materials%20Extension.md). Supported core units convert to mm, with Z up. Resources are defined before references; repeated/nested component occurrences remain separate and accumulated transforms retain reflection. Only referenced vertices determine the local float origin. Facet normals and UV seams are preserved. There is no artificial vertex, face or component-depth ceiling; runtime capacity, numerical precision and available memory still apply.

Base-material sRGB RGBA retains coverage alpha. Direct `colorgroup` triangles must have a uniform color; direct color/texture alpha is ignored as specified for a base layer. `texture2dgroup` supports independent per-corner UV indices, object defaults and missing p2/p3 fallback to p1. PNG/JPEG resources must have an actual package relationship and matching declared/image MIME; both generic texture and matching image content types are accepted, as emitted by the [official writer](https://github.com/3MFConsortium/lib3mf/blob/bfb5df00057fae7e306c511fa7c6ff476dfaad28/Source/Model/Writer/NMR_ModelWriter_3MF_Native.cpp#L114-L119). Wrap/clamp and nearest/linear sampling are carried into the shared texture snapshot (`auto` chooses linear). Direct-layer `none` uses clamp because alpha is ignored. Encoded images are privately retained and embedded into the candidate.

Explicit remaining boundaries: vertex-color gradients, mirrored tiling, multiproperties, composite/display materials, production/slice/vendor data and editable assembly hierarchy. The shared bitmap reader currently requires 8-bit RGB/RGBA PNG or supported three-channel JPEG; palette/grayscale images and embedded ICC/EXIF color management are not covered. Static triangle preview does not reconstruct manufacturing positive-fill/overlap rules. Unsupported content fails instead of yielding an apparently complete partial scene. This is neither full Materials conformance nor a native appearance acceptance claim.

## Native 3MF acceptance, still pending

On Mac and Windows, load the packaged `fixtures/mesh-core.3mf`: blue/orange tetrahedra, mirrored component, centimetre units, expected mm bounds X 0–30, Y 20–30, Z 0–10 and 8 triangles. Compare the plugin candidate to native import if available, then verify one Block, Undo/Redo, repeated-acceptance protection and save/reopen persistence.

Also load `fixtures/mesh-textured.3mf` (reproduce/check with `fixtures/create-textured-3mf.py --check`). Use **scene coordinates** or **original size** because it is planar. It contains three parts/five triangles, expected mm bounds X 0–40, Y 10–50, Z 0. Viewed from +Z with +Y up, the first square's top corners are red/green and bottom corners blue/yellow. All four remain opaque despite image alpha. The mirrored second square has cyan/white top corners and black/magenta bottom corners. The separate blue triangle is half opaque (128/255). Check nearest sampling, correct image-to-part association and no double reflection. Move to another CPlane/point; after accepting, delete candidate temporary files, save/reopen and confirm embedded images remain. Source files/hashes must stay unchanged.

Test unsupported gradients/mirror tiling/multiproperties/production content, malformed or external/missing references and cancellation: no document mutation or partial placement. Cancel/switch documents/change units or color preprocessing during preparation. These cases and exact native UV/filter/opacity appearance remain unaccepted on both platforms. A Mac-built Windows archive is not Windows execution.

## Local ordinary USD import

The local mesh action uses pinned OpenUSD 26.11, independently from the GS import action. It privately copies the source and its dependency closure before extraction; plain working layers relocate only asset-path opinions to private files. The exact copied root and dependency hashes are preserved separately from the derived self-contained 3DM hash. This is not a claim of an atomic multi-file save by the source application. USDZ must remain self-contained; a plain USD referencing external USD packages is currently rejected. No GLB intermediate or artificial geometry quota is used.

Static Mesh triangles/quads, simple planar n-gons, valid material face subsets, native instances, Y/Z axes and physical units are supported. Constant/uniform/vertex/varying/face-varying normals and st UVs, including indexed primvars, are resolved and split at seams. PBR Preview Surface constants and a directly connected sRGB PNG/JPEG can be retained, including ignored bitmap alpha with partial material opacity. The strict unsupported boundary includes subdivision, holes, nonplanar/self-intersecting n-gons, invalid/overlapping/non-material subsets, point instancers, animation/clips/skinning, hidden/guide/proxy meshes, other geometry types, general shader graphs and non-default shading features. Two-sided Rhino display is reported explicitly; the authored culling flag remains metadata.

Rhino document settings are captured on UI; independently owned geometry/3DM construction runs in a worker. Native preflight and final import remain UI operations. Standalone File3dm reads/writes cannot be interrupted inside their native call; cancellation is observed around them. Units, tolerance and color preprocessing are checked again before preparation/commit. The final texture references rely on Rhino resolving the embedded images after temporary paths disappear; package byte readback is verified, while this host behavior still needs native acceptance. Candidate placement offers fit-height/CPlane (default), original-size/CPlane and preserved scene coordinates. Source coordinates are the prepared geometry after units, up-axis and scene-transform conversion. Original-size and scene-coordinate modes allow zero-height planar meshes. Disabled height/rotation/point controls are not parsed; invalid bounds or non-finite resulting coordinates still fail explicitly.


## Task result placement

USD task results now share the local USD preparation path for preview, direct placement and original-generation automatic placement. The selected task/account/region/remote ID, operation, output key/format and any recorded source hash remain pinned across download. Known outputs use one download request (the sidecar already refreshes the original task); no new generation is submitted. World Gaussian PLY is routed separately from object mesh PLY.

Preview acceptance and direct placement share the same task/output receipt. A receipt is checked before source acquisition, so an existing or undone placement can be resolved offline even after cache deletion. Prepared candidates are released on Rhino's UI thread after success, failure, cancellation, deferral or a duplicate detected during preparation. Cached source bytes still undergo snapshot/hash and geometry checks before native import.


## Local mesh command and placement modes

`AholoImportMesh` accepts a path in scripted mode or opens a file picker interactively. It opens the original document's Library and waits for the command/Undo cycle to finish before preparing a candidate. It retains the panel's chosen placement mode and does not commit automatically. A busy/closed panel, changed document or expired wait produces explicit feedback. `AholoCancel`, document closure and plugin shutdown clear the pending request.

Fit-height and original-size modes anchor the source XY midpoint/minimum Z to the selected point on the captured CPlane, then apply Z rotation. Scene coordinates disable those controls and use identity placement. Switching/removing/accepting candidates preserves the mode. Acceptance now passes the panel operation cancellation token and revision/visibility guard through the native commit checkpoints.


## USD polygon faces and material groups

Faces with five or more corners use deterministic ear clipping after planarity and simple-boundary validation. Orientation/intersection predicates share an exact binary-rational fallback near floating-point cancellation. The planarity tolerance is relative to face extent (1e-6); it is a numerical tolerance, not a geometry-count limit. Original corners, winding and collinear boundary vertices remain; only internal edges are added. Repeated corners, boundary self-crossing/touching/backtracking, zero-area and nonplanar n-gons fail explicitly. There is no fan fallback. Triangles and strictly convex planar quads retain their native route. Valid planar concave quads and quads with a retained collinear boundary corner are triangulated; invalid planar boundaries fail. Exact coplanarity distinguishes even a tiny real 3D warp, which retains the native quad route rather than being rejected from its 2D projection. Very high-sided individual polygons can be expensive; cancellation terminates the worker process. Dense meshes use compact corner offsets and generated-normal arrays; transient source-face points are not retained for every face.

Only static face `GeomSubset` children in the `materialBind` family are accepted, with a valid `partition` or `nonOverlapping` family. Empty subsets add no geometry. Face ownership is checked for overlaps, repeated/out-of-range indices and partition gaps. Unassigned faces inherit the mesh binding. Effective bindings resolve through OpenUSD, including inherited stronger bindings and collection bindings; the viewer selects `preview` with all-purpose fallback, then `full` only when no preview/all-purpose binding exists. This policy is not a claim that every shader network is supported. See the official [material-binding rules](https://openusd.org/release/api/class_usd_shade_material_binding_a_p_i.html) and [subset validity rules](https://openusd.org/release/api/class_usd_geom_subset.html).

Each material group becomes a separate mesh part with the original Mesh path and actual subset path retained separately (`Aholo.Mesh.SourcePrim` and `Aholo.Mesh.SourcePart`). For the unassigned residual faces both values are the Mesh path; subset parts carry their actual subset path in SourcePart. Face-uniform attributes use original face numbers, and indexed face-varying normals/UVs use original global corner numbers even after triangulation and splitting. Authored normals are retained, with `primvars:normals` taking precedence. Without either normal source, each original face gets one area-vector normal before triangulation or material splitting; vertices split across original faces to retain flat shading even without UV seams. Left-handed orientation is applied once to generated normals; authored normals use the normal transform without an extra orientation flip. Generated provenance is retained in `Aholo.Mesh.GeneratedFacetNormals`. This follows the pinned [USD mesh schema](https://github.com/PixarAnimationStudios/OpenUSD/blob/v26.11/pxr/usd/usdGeom/schema.usda#L1006-L1021) and [flat-normal implementation](https://github.com/PixarAnimationStudios/OpenUSD/blob/v26.11/pxr/imaging/hd/flatNormals.cpp#L29-L44). Exact arithmetic resolves near cancellation before converting the generated direction to float32; it does not make geometry or Rhino storage arbitrarily precise. Editable USD hierarchy and subset reassembly on export are not promised.

`fixtures/mesh-subsets.usda` is a self-contained metres/Z-up sample: green triangle, blue concave five-corner face and red quad. Its planar source should use Original size or Preserve scene coordinates rather than fit-height. Import should produce three material parts with one triangle, three triangles and one quad respectively; blue source area is 6 square metres. Native color, normals, Undo and persistence still require manual acceptance on both platforms.


## OBJ and typed OBJ archives

Local OBJ/ZIP and task `obj_zip` use the independent .NET reader, with no Python dependency. See [OBJ import and acceptance](obj-import-development.md) for material limits, explicit source coordinates, frozen archive selection, smoothing, metadata and deterministic native samples. All OBJ polygons, including quads, are validated and triangulated; this differs from the current USD quad route. Generic ZIP task outputs and FBX remain unsupported. Each task/output retains one placement receipt; load its downloaded ZIP locally to choose another entry. Native embedded-image resolution, visual correctness and Undo remain pending on both platforms.


## Native face-material capture

Local mesh/scene USD export and offline render capture share the same source material resolution. Top-level MaterialFromParent follows Rhino's layer fallback; inside a block, the actual effective parent is retained. Brep face channel numbers are resolved against that effective base material, then the resulting material GUID is looked up in the current document. A channel number is never treated as a document-table index. Undefined channels inherit the effective base; unresolved nonempty IDs fail. See the [official face-channel explanation](https://discourse.mcneel.com/t/face-materials/130746/2) and [component material API](https://developer.rhino3d.com/api/rhinocommon/type/rhino.docobjects.rhinoobject/?member=getmaterial-rhino.geometry.componentindex).

Faces with supported overrides are meshed individually from private copies, except surface-textured Breps use their original per-face render caches as described below; no ordering of whole-Brep mesh outputs is assumed. Extrusion wall/cap component IDs map through `GetBrepFormComponentIndex` to `ToBrep(false)` faces; ambiguous, unmappable or conflicting components fail explicitly. Simple objects retain their aggregate mesh path. Ordinary Mesh objects do not expose a native per-face material channel; use separate mesh objects/Block members for separate materials. Unknown sub-object material configurations are not silently flattened.

Only consumed materials are decoded, so an unused parent bitmap cannot invalidate children with explicit supported overrides. Existing supported legacy base color/PBR constants are retained per part; object and original-cache surface mappings are supported as described below, while arbitrary material graphs and display-only per-face colors remain outside this change. Default-material component configurations without a usable material-table index are explicitly unsupported; unassigned/default materials on ordinary objects still work. Native material references stay inside synchronous UI capture. Geometry/UV transformations and disposal affect private copies; a missing original render cache may be prepared on the source object without changing its geometry or assignments.

Both cloud and local export now transform private double-precision meshes and use Rhino's quad triangulation. A conversion that removes a source corner by producing fewer than two triangles per quad fails instead of silently dropping its attributes. Final cloud GLB positions still use float32; this is not an arbitrary-precision export claim. Native visual/material/Undo/source-preservation acceptance remains pending.


## Bitmap mapping capture

A selected bitmap now keeps its projection and mapping-channel identity. Channel lookup follows the [official request → channel 1 → surface fallback](https://github.com/mcneel/opennurbs/blob/8.x/opennurbs_texture.h#L276-L286). Explicit surface parameterization bypasses custom channels. A matching parent-block channel is rejected until instance mapping precedence is accepted; unrelated ancestor channels do not block a leaf's selected mapping. Legacy channel 0 is rejected explicitly rather than assumed equivalent to channel 1. WCS, OCS, environment, screen and custom primitive mappings are not part of this feature.

Plane, box, cylinder and sphere mappings are calculated on private leaf-local mesh geometry, including meshes tessellated from Breps/extrusions. `GetTextureMapping`'s object transform is passed unchanged to Rhino; instance/world/unit transforms happen later. The SDK handles UV seams before vertex/normal/index arrays are captured. Source normals are prepared before splitting so newly duplicated vertices keep the original smoothing. Mapping UVW is applied by Rhino, bitmap UVW by the portable transform, then V is converted to the existing glTF convention. Both UVW transforms must be finite two-dimensional affine transforms; there is no UV range clamp. See the [fixed API implementation](https://github.com/mcneel/rhino3dm/blob/8.x/src/dotnet/opennurbs/opennurbs_mesh.cs#L4035-L4068).

For native Mesh surface mapping, existing surface parameters take precedence over a different current UV array. Where parameters are absent, Rhino's supported UV-to-surface-parameter conversion is attempted on the private copy. Both old UV and mapping caches are cleared before the boolean surface calculation, so a failed native calculation cannot pass merely by leaving old or zero-filled coordinates. Count and finite-value checks still apply. Surface-textured Breps instead copy each original face render mesh and retain its [surface parameters, packed domains and rotation](https://github.com/mcneel/opennurbs/blob/8.x/opennurbs_material.cpp#L5249-L5369). Material bindings follow the original Brep face index. The source is never replaced by an individually remeshed face for this route.

The offline checks prove channel policy, affine calculation order and emitted GLB coordinates. Actual Rhino mapping, smoothing, image orientation, native packing and cloud visual parity require manual acceptance. Bitmap files, alpha/wrap/filter controls and immutable file snapshots retain their existing limits.


## Original surface render caches

When a consumed bitmap resolves to surface parameterization, capture uses each original Brep face's render cache. Missing or incomplete caches trigger one whole-object `CreateMeshes(Render, object.GetRenderMeshParameters(), false)` preparation, respecting per-object/document mesh settings. The object is rechecked and its geometry is reacquired afterward; each face must have a nonempty cache. Creation count is not used as a face-order or completeness claim. This may populate runtime rendering caches; it does not add/delete geometry, change material or mapping assignments, or clear existing caches on failure. All captured meshes are privately duplicated before UV/normal/transform work.

The borrowed mesh relationship is explicit in [BrepFace.GetMesh](https://github.com/mcneel/rhino3dm/blob/8.x/src/dotnet/opennurbs/opennurbs_brep.cs#L6604-L6616), while [mesh duplication](https://github.com/mcneel/opennurbs/blob/8.x/opennurbs_mesh.cpp#L474-L539) retains surface and packing data. Original-cache UVs are rebuilt from that data after clearing mapping caches. Unlike authored Mesh objects, missing surface parameters are never inferred from the current UV array, because that array may belong to another mapping. A failed native surface calculation aborts capture rather than substituting zero or stale UVs.

An Extrusion's whole original render cache is used only when every effective face has the same material identity and complete supported appearance (including bitmap/channel/UVW). A common overriding face material is retained instead of the object's unused base. Divergent face materials combined with surface UVs remain unsupported: [Extrusion.ToBrep(false)](https://github.com/mcneel/opennurbs/blob/8.x/opennurbs_beam.cpp#L2563) constructs new geometry without transferring original meshes, and no public map from the aggregate cache's mesh faces to original components was established. Convert such an extrusion to a polysurface, use supported explicit object mapping, or disable bitmap export. Missing/unrecoverable original surface parameters also remain an explicit failure.

Native cache creation, extrusion surface metadata, packed rotation, trimmed faces and visual fidelity are pending Mac/Windows acceptance. Release compilation, source review and existing offline transport tests do not establish those behaviors.


### Independent bitmap alpha and material opacity

For GLB-based cloud preparation, an 8-bit RGBA PNG may ignore its alpha channel while retaining a partial material opacity. Only the GLB payload is normalized to RGB; original encoded images, persisted sources and USD texture payloads stay unchanged. The original RGB samples include colors hidden behind zero alpha. See [conversion boundaries and independent validation](png-alpha-export.md).
